# korotkiy-url - Стратегии деплоя (ДЗ 8)

## Примечания
Добавлена ручка /version, возвращает под и версию приложения (версия передается в бекенд как переменная окружения)

Запущено 3 реплики через Deployment

Все запросы на приложение шли через Envoy Gateway:

```
kubectl port-forward -n envoy-gateway-system svc/envoy-app-default-gateway-cd9693e4 8080:80

```

Для каждой стратегии прикрепил скринкаст и соответствующие манифесты (папка strategies)

Liveness и readyness пробы есть

## RollingUpdate
В backend.yml в деплойменте меняем темплейт пода: ставим переменную окружения APP_VERSION = v2 вместо v1 (на практике обновляют образ, но суть та же)

Создаются новые поды и трафик постепенно переходит от v1 к v2

## Blue/Green
В backend.yml создаем два деплоймента и сервиса для двух разных версий приложения

В HTTPRoute меняем backendRef на вторую версию

Мгновенный переход всего трафика с версии 1 на версию 2

Откат делается точно также: возвращаем прошлую версию -> мгновенный переход всего трафика обратно

## Canary
В HTTPRoute с помощью весов постепенно увеличиваем долю трафика на новую версию в несколько шагов:
- 100/0
- 90/10
- 50/50
- 10/90
- 0/100

## A/B
При наличии HTTP хэдера x-user-group со значением beta направляем на новую версию, иначе на старую

## Shadow
Весь трафик идет на первую версию и зеркалируется на вторую; ответ приходит только от первой версии, но по логам можно увидеть, что вторая тоже получает запросы
