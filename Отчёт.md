# korotkiy-url

## 1. Доменная область

Сервис сокращения ссылок со статистикой переходов.

Пользователь создает короткую ссылку для URL (код можно сгенерировать автоматически или вписать вручную) и делится адресом вида `http://<хост>/s/<код>`. При переходе по такой ссылке сервис перенаправляет посетителя на исходный адрес и записывает переход: время и источник. Через фронтенд можно создавать, просматривать, редактировать и удалять ссылки, а также смотреть историю переходов по каждой из них

## 2. Стек реализации

Бэкенд: Go 1.27, net/http, pgx, golang-migrate
База данных: PostgreSQL 17
Фронтенд: TypeScript, Svelte, Vite, svelte-spa-router

## 3. Основные сущности

### Link - короткая ссылка:

| Поле | Описание |
|---|---|
| `id` | идентификатор |
| `short_code` | короткий код |
| `original_url` | исходный адрес |
| `created_at` | время создания |

### Click - один переход по короткой ссылке:

| Поле | Описание |
|---|---|
| `id` | идентификатор |
| `link_id` | к какой ссылке относится |
| `timestamp` | время перехода |
| `referrer` | значение заголовка `Referer` |

## 4. Инструкции по запуску
```
git clone https://github.com/ustkost/korotkiy-url.git
cd korotkiy-url
cp .env.example .env
docker compose up --build
```

## 5. Соответствие 12 факторам

### I. Codebase - соответствует
Весь код хранится в одном репозитории: бэкенд, фронтенд, миграции и т.д.

### II. Dependencies - соответствует
Зависимости объявлены явно и зафиксированы в `go.mod` и `go.sum` для бэкенда и в `package.json` и `package-lock.json` для фронтенда

### III. Config - соответствует
Вся конфигурация, отличающаяся между окружениями, берётся из переменных окружения: порт, параметры подключения к БД (`DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`), уровень логирования (`LOG_LEVEL`).

### IV. Backing services - соответствует
PostgreSQL подключается как внешний ресурс по адресу из переменных окружения.

### V. Build, release, run - соответствует
Сборка - `docker compose build`, выполнение - `docker compose run`

### VI. Processes - соответствует
Бэкенд - stateless процесс, все данные хранятся в БД

### VII. Port pinding - соответствует
Бэкенд является самодостаточным HTTP-сервером, сам слушает порт из переменной окружения`PORT`. Nginx используется для раздачи статики и как обратный прокси, но работа бэкенда от него не зависит.

### VIII. Concurrency - соответствует
Можно масштабировать приложение с помощью запуска нескольких экземпляров бэкенда.

### IX. Disposability - соответствует
Контейнеры можно перезапускать не беспокоясь о потере данных; бэкенд запускается быстро, имеется graceful shutdown

### X. Dev/prod parity - соответствует частично
В dev окружении та же самая кодовая база и те же инструменты, что в prod. Единственное отличие - используется `npm run dev` вместо `npm run build` для фронтенда, но я считаю это допустимым

### XI. Logs - соответствует
С помощью `log/slog` бэкенд пишет логи в stdout в формате JSON

### XII. Admin processes - соответствует
Миграции для БД выполняются как отдельный одноразовый процесс с помощью `golang-migrate`
